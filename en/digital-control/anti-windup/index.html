Anti-windup and duty saturation

When the duty hits its limit, the integrator must not keep accumulating error: the integrator clamp, the 2p2z velocity form and back-calculation.

First, see: The 2p2z compensator

The duty has limits, and the linear 2p2z compensator doesn't know it. This note shows, step by step, how to keep an integrator from accumulating error while the output is saturated.

1. Saturate the duty

Every controller ends with a clamp to [dmin⁡,dmax⁡][d_{\min}, d_{\max}][dmin​,dmax​]. In the buck, dmin⁡d_{\min}dmin​ = 0 and dmax⁡d_{\max}dmax​ = 0.9. Besides the physical limit between 0 and 1, a maximum below 1 leaves time for the driver's bootstrap capacitor to recharge and an off interval to measure current. With dmax⁡=0.9d_{\max} = 0.9dmax​=0.9, the buck only delivers 15 V if the input is above about 17 V.

2. Understand windup

While the output is saturated, the loop is open: raising the command changes nothing. The integrator keeps adding the error, and that excess must be discharged later, with an error of the opposite sign, that is, with overshoot.

The PID of scenario.cpp and buck_pid.cpp uses the simplest solution, the integrator clamp: the state is limited to the same range as the duty.

integ += KI * T * err;
if (integ < DMIN) integ = DMIN;        /* anti-windup by clamping */
if (integ > DMAX) integ = DMAX;
d = KP * err + integ + deriv;
if (d < DMIN) d = DMIN;
if (d > DMAX) d = DMAX;

The clamp prevents the worst, but the integrator can still sit at dmax⁡d_{\max}dmax​ when the operating point needs much less, and the output overshoots the reference while it unwinds. The "In the converters" section measures that overshoot in the boost.

3. Or use the velocity form

The 2p2z in C computes each duty from the two previous ones (equation Difference equation of the 2p2z) and stores the saturated ones. No state grows past the limits: the form is anti-windup by construction.

It has one flaw, though. When a jump in the error saturates the duty, the next period's term b1 e[k−1]b_1\,e[k-1]b1​e[k−1] takes back the whole kick, which was never applied, and the duty plunges the other way.

4. Back-calculation

An alternative to the clamp is to feed back to the integrator the difference between the saturated and the computed command, with a time constant TtT_tTt​:

xI[k+1]=xI[k]+KI Ts e[k]+TsTt (dsat[k]−d[k]).x_I[k+1] = x_I[k] + K_I\,T_s\,e[k] + \frac{T_s}{T_t}\,\bigl(d_{\mathrm{sat}}[k] - d[k]\bigr).xI​[k+1]=xI​[k]+KI​Ts​e[k]+Tt​Ts​​(dsat​[k]−d[k]).

Outside saturation, the new term is zero. In saturation, it pulls the integrator to the value that keeps the command at the limit. A rule of thumb is Tt=Ti TdT_t = \sqrt{T_i\,T_d}Tt​=Ti​Td​​, with Ti=KP/KIT_i = K_P/K_ITi​=KP​/KI​ and Td=KD/KPT_d = K_D/K_PTd​=KD​/KP​.

/* PID with back-calculation; deriv comes from the derivative term */
float pid_step(float e, float deriv)
{
    float d = KP * e + integ + deriv;
    float dsat = d < DMIN ? DMIN : d > DMAX ? DMAX : d;
    integ += KI * T * e + (T / TT) * (dsat - d);   /* back-calculation */
    return dsat;
}

The most common trigger of saturation is the jump of the derivative term on a reference step, and computing the derivative on the measurement avoids it: see Derivative kick and derivative on the measurement.
