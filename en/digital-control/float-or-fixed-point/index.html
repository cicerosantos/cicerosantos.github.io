Floating point or fixed point

Between `float` and fixed point, the core decides first: without an FPU, fixed point is the output; with an FPU, the choice is a design one, and only a cycle measurement justifies it.

First, see: The 2p2z compensator

The 2p2z compensator equation can run on floating-point numbers, which the core computes with the coefficients as they are, or on fixed-point integers, each with an implicit scale (Q15 fixed point). The choice depends first on what the core has in hardware, and then on what measurement shows.

By the core's hardware

  • With a single-precision FPU (Cortex-M4F, M33 and others): use float. On the M4F, an addition or a multiplication takes 1 cycle, and a multiply-accumulate 3 (Cortex-M4 TRM, table 7-1); for the M33, see the core's manual. The 24-bit mantissa is enough for this loop.
  • With a double-precision FPU (the H7's Cortex-M7, PM0253): float and double both run in hardware, and choosing between them and fixed point is a design decision. Fixed point saves cycles only if measurement shows it. This note has no such measurement for the H7, and claims no speed-up without a number.
  • Without an FPU (Cortex-M0 and M0+): each float operation becomes a library call, typically tens of cycles. With a 5 µs period and a 64 MHz core, there are only 320 cycles per period, and fixed point is used there.

Hidden double precision

On a single-precision FPU (M4F, M33), 0.5 is a double, and x * 0.5 is computed in software. Write 0.5f, and compile with -Wdouble-promotion so the compiler points at the cases. On the H7 double precision also runs in the FPU, but promotion still changes the result type: write 0.5f to keep float.

Measure before switching

Fixed point is not justified by the mere existence of an FPU. On the H7, the fixed-point variant comes in only if measuring the float routine shows that it does not fit the deadline with the margin the design needs. The measurement is the one in Interrupt deadline and budget: an output pin and the DWT cycle counter, on production code. With the number in hand, the decision is a margin calculation.

Fixed point has costs of its own, which the FPU does not remove:

  • Scale: each quantity has a format, and the coefficient range is checked before the coefficients are written (Q15 fixed point).
  • Fraction bits in the states: the states keep the 12 fraction bits. Without them, the integrator's steps, hundredths of a count, would round to zero, as DPWM resolution and limit cycles warns.
  • Saturation: every sum that can leave the range saturates, because an integer wrap-around sends the duty cycle from its maximum to a negative value.

Fixed-point variant

The error stays in ADC codes, the duty cycle in HRTIM counts with 12 fraction bits, and the coefficients in Q3.12, as in Q15 fixed point. The numbers are for 2000 counts per period:

#define FRAC      12
#define REF_CODE  1843                                    /* 9 V * 4095 / 20 V = 1842.75 */
static const int32_t b0q = 9248, b1q = -17369, b2q = 8156;   /* Q3.12: |b1| = 4.24 does not fit Q2.13 */
static const int32_t a2q = 4975;                             /* a2 = p in Q15; a1 = -(1 + a2) */
static const int32_t UMIN = 3 << FRAC;                       /* CMP1xR >= 3 (RM0433, table 308) */
static const int32_t UMAX = 1800 << FRAC;                    /* 0.9 * 2000 counts */
static int32_t uq1 = 750 << FRAC, uq2 = 750 << FRAC;         /* 0.375 * 2000 */
static int32_t eq1, eq2;

void ADC_IRQHandler(void)
{
    int32_t e = REF_CODE - (int32_t)ADC1->DR;              /* error in codes: can be 0 */
    int64_t d = (int64_t)a2q * (uq1 - uq2);                /* up to 3.7e10: only this product needs 64 bits */
    int32_t acc = uq1 + (int32_t)((d + (1 << 14)) >> 15)
                + b0q * e + b1q * eq1 + b2q * eq2;         /* sum below 1.6e8: fits 32 bits */
    if (acc < UMIN) acc = UMIN;                            /* saturate in Q12 counts */
    if (acc > UMAX) acc = UMAX;
    uq2 = uq1; uq1 = acc;
    eq2 = eq1; eq1 = e;
    HRTIM1->sTimerxRegs[0].CMP1xR = (uint32_t)((acc + (1 << (FRAC - 1))) >> FRAC);   /* timer A */
}

In the converters

Buck. At 200 kHz, the period has 2000 HRTIM counts at 400 MHz, that is, 2000 core cycles. That is the deadline the routine must meet, and the measurement in Interrupt deadline and budget says whether it does. In the standard design the coefficients in counts per code fit Q3.12, and the code above is the fixed-point counterpart of the float routine in The 2p2z in C, in the interrupt. The integer reference 1843 regulates at 1843×20/4095=9.00121843 \times 20/4095 = 9.00121843×20/4095=9.0012 V.

Boost. At 100 kHz, the period has 4000 cycles, twice the buck's deadline; the margin grows by more than that, because the routine takes the same time. The coefficient scale changes with the ADC range, 60 V, as Q15 fixed point shows.

Exercise 1

A Cortex-M0+ at 64 MHz, with no FPU, drives the buck at 200 kHz. How many cycles are there per period? Why is the float variant risky?

Answer

64 MHz×5 µs=32064\ \text{MHz} \times 5\ \text{µs} = 32064 MHz×5 µs=320 cycles. The float routine has about ten library operations, each of tens of cycles: they come close to 320 cycles or exceed it, depending on the cost of each, which depends on the library, and no margin is left for the rest of the interrupt. In fixed point, the same routine is a few 32-bit integer multiplications and one 64-bit one, which the compiler turns into a library call, because the M0+ has no 64-bit multiply.

Exercise 2

A Cortex-M4F program writes float x = y * 0.5;. Which part makes the operation run in double precision in software, and what does the compiler warn about with the right option?

Answer

The literal 0.5 without f is a double, and y * 0.5 promotes the operation to double, computed in software on the M4F. Writing 0.5f keeps float, and -Wdouble-promotion points to the promoting line.
