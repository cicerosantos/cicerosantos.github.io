The 2p2z in C, in the interrupt

The buck's interrupt in C: read the ADC, compute the error, run the 2p2z difference equation, saturate and write the CCR, with protection against NaN, fault, double-buffered coefficients and ADC overrun.

First, see: Interrupt deadline and budget, Q15 fixed point, Anti-windup and duty saturation

This note brings together what the trail built. The 2p2z compensator becomes the difference equation below, and the saturation from Anti-windup and duty saturation sits at the output:

The sequence in each period

  1. The timer triggers the ADC at the sampling instant. In the boost and buck-boost scenarios (scenario.cpp), SAMPLE_PHASE = 0; the buck's frames come from the older version of the qspice-wine live demo, which sampled at the period start, with one period of delay. On a board, see ADC trigger and sample instant.
  2. The ADC finishes the conversion and calls the interrupt.
  3. The interrupt computes the error and the new duty cycle, and saturates it.
  4. It writes the CCR. With preload on, the new value takes effect only at the next update event.

Step 4 is what scenario.cpp imitates with s->duty = s->pending: the duty cycle computed from the sample of period kkk governs period k+1k+1k+1. With trailing-edge PWM, the total delay is (1+D) Ts(1 + D)\,T_s(1+D)Ts​, the subject of Computation and PWM delay.

Preload off

Do not turn preload off to gain a period. Without it (the PREEN bit of HRTIM_TIMxCR on the H7; OC1PE on a general-purpose timer), the new compare value takes effect at once. If it is written below the counter's current value, the effect depends on the timer: on a general-purpose timer in PWM mode, the output drops at once and the pulse comes out shortened; on the HRTIM, which turns on and off through events, the turn-off comparison has already passed, and the switch stays on until the next period's turn-off, a pulse that is too long, the dangerous case. The double pulse is the opposite case: a larger value written after the falling edge. Keep preload on and accept the one-period delay that the design in Computation and PWM delay already includes.

Float variant (with FPU, as on the H7's Cortex-M7)

This is the logic of scenario.cpp, with the error in volts and the standard buck design coefficients. The routine adds what a board firmware needs and the simulator does not have:

  • NaN: a comparison with NaN is false. The test !(x >= lo) catches NaN, and the routine never writes NaN to the states or to the CCR.
  • Enable and fault: ctrl_enable and ctrl_fault. When disabled or faulted, the routine switches the outputs off through HRTIM_ODISR and clears the states. On the synchronous buck, that also switches the low-side switch off: it shuts the converter down, it does not ask for DMIN. Only the main loop re-enables, in this order: it clears ctrl_fault, sets ctrl_enable = 1 and writes HRTIM1->sCommonRegs.OENR = HRTIM_OENR_TA1OEN | HRTIM_OENR_TA2OEN. The states restart from DMIN, and the start follows Soft-start and pre-biasing; it is also worth clearing the ADC's OVR (ADC_ISR_OVR) at that moment.
  • Double-buffered coefficients: the main loop writes to the inactive set and only then switches the index. The interrupt reads the index once.
  • ADC overrun: with OVRMOD = 1, set at initialization, a lost conversion raises the OVR flag (Interrupt deadline and budget). With it, or with a full-scale code, the sample is not valid, and the routine holds the CCR and counts.
  • Minimum compare: the HRTIM needs CMP1xR ≥ 3 (PWM timer and shadow registers). So DMIN = CMP_MIN/PWM_N = 0.0015, and the state saturates where the CCR does. The simulated scenarios use DMIN = 0; the board code uses the 3-count floor.
#include <stdint.h>
#include "stm32h7xx.h"                  /* or your MCU's CMSIS header */

#define PWM_N     2000u                 /* 400 MHz / 200 kHz: HRTIM counts per period */
#define ADC_MAX   4095u                 /* 12 bits: codes 0 to 4095 */
#define LSB       (20.0f / 4095.0f)     /* volts per code, range 0 to 20 V */
#define CMP_MIN   3u                    /* RM0433, table 308: CMP1xR >= 3 */
#define DMIN      ((float)CMP_MIN / PWM_N) /* 0.0015: the state saturates where the CCR does */
#define DMAX      0.9f
#define E_MAX     20.0f                 /* largest accepted error, in volts */

typedef struct { float b0, b1, b2, a2; } coef_t;   /* a1 = -(1 + a2) */

static coef_t coef_buf[2] = {                       /* two sets: the active and the inactive one */
    { 0.23114164f, -0.43413087f, 0.20384645f, 0.15183580f },
    { 0.23114164f, -0.43413087f, 0.20384645f, 0.15183580f },
};
static volatile uint8_t coef_sel;                   /* index of the active set; the ISR and coef_update read it */
static volatile float vref = 9.0f;                  /* written by the main loop */
static volatile uint8_t ctrl_enable;                /* 1: closed loop */
static volatile uint8_t ctrl_fault;                 /* 1: latched fault; only the main loop clears it */
static volatile uint32_t overrun_count, hold_count; /* diagnostics */
static float u1 = 0.375f, u2 = 0.375f, e1, e2;     /* states; start at the steady-state duty */

/* Once, before the loop and with ADSTART = 0: enable the FPU (CP10 and
   CP11 with full access) and set OVRMOD = 1, so OVR rises at the first missed read. */
void ctrl_init(void)
{
    SCB->CPACR |= (3UL << (10 * 2)) | (3UL << (11 * 2));
    __DSB();
    __ISB();
    ADC1->CFGR |= ADC_CFGR_OVRMOD;
}

/* Main loop: write the inactive set, then switch the index. */
void coef_update(const coef_t *n)
{
    uint8_t next = coef_sel ^ 1u;
    coef_buf[next] = *n;                            /* the ISR does not read this set */
    __DMB();                                        /* the copy finishes before the switch */
    coef_sel = next;
}

/* Disabled or faulted: outputs off and states cleared, no NaN. */
static void ctrl_safe(void)
{
    u1 = u2 = DMIN;
    e1 = e2 = 0.0f;
    HRTIM1->sCommonRegs.ODISR = HRTIM_ODISR_TA1ODIS | HRTIM_ODISR_TA2ODIS;  /* idle state */
}

void ADC_IRQHandler(void)                           /* ADC1 and ADC2 share the vector (ADC_IRQn = 18) */
{
    const coef_t *c = &coef_buf[coef_sel];          /* read the index once per interrupt */
    uint32_t raw = ADC1->DR;                        /* reading DR clears the end-of-conversion flag */

    GPIOB->BSRR = GPIO_BSRR_BS0;                    /* measurement pin: high */

    if (!ctrl_enable || ctrl_fault) {
        ctrl_safe();
    } else if (ADC1->ISR & ADC_ISR_OVR) {           /* overrun: the conversion was lost */
        ADC1->ISR = ADC_ISR_OVR;                    /* clear the flag (write 1) */
        overrun_count++;
        hold_count++;                               /* hold the previous duty cycle */
    } else if (raw >= ADC_MAX) {                    /* full scale: input out of range */
        hold_count++;
    } else {
        float e = vref - (float)raw * LSB;
        if (!(e >= -E_MAX && e <= E_MAX)) {         /* NaN lands here: the comparison is false */
            ctrl_fault = 1;
            ctrl_safe();
        } else {
            float u = u1 + c->a2 * (u1 - u2) + c->b0 * e + c->b1 * e1 + c->b2 * e2;
            if (!(u >= DMIN)) u = DMIN;             /* NaN and values below DMIN */
            if (u > DMAX) u = DMAX;                 /* saturation: anti-windup */
            u2 = u1; u1 = u;
            e2 = e1; e1 = e;
            uint32_t cmp = (uint32_t)(u * PWM_N + 0.5f);
            HRTIM1->sTimerxRegs[0].CMP1xR = cmp < CMP_MIN ? CMP_MIN : cmp;  /* preload: takes effect in the next period */
        }
    }
    GPIOB->BSRR = GPIO_BSRR_BR0;                    /* measurement pin: low */
}

u1 + a2*(u1 - u2) is the same as -a1*u1 - a2*u2, because a1=−(1+a2)a_1 = -(1 + a_2)a1​=−(1+a2​): it is the velocity form, which computes the increment Δu\Delta uΔu and adds it to u1. Written this way, it does without a1=−1.15a_1 = -1.15a1​=−1.15, which does not fit Q15 in the fixed-point variant, and the integrator sits exactly at z=1z = 1z=1. The reference can also gain a ramp, adding a limited step to vref at each interrupt: that is the subject of Soft-start and pre-biasing.

Fixed-point variant

The fixed-point variant, with the 2p2z in counts per code and Q3.12, is in Floating point or fixed point (the code) and Q15 fixed point (the coefficient scale).

Neither the variant in this note nor the one in Floating point or fixed point has been simulated: scenario.cpp computes in double, and the recorded scenarios start in steady state, so the start-up and the fixed-point arithmetic have not been checked on the QSPICE.

Interrupt deadline

What this routine has to meet, and what consumes it, is in Interrupt deadline and budget. In the buck, there are 2000 cycles per period at 400 MHz; the write to the CCR must arrive before the update event. Measure the routine on the production code before trusting any cycle count.

In the converters

Buck. At 200 kHz, the period has 2000 cycles at 400 MHz, the same number of HRTIM counts, because the HRTIM counts on the core clock (HRTIMSEL = 1, as in DPWM resolution and limit cycles). The reference stays in volts, vref = 9.0f; the integer reference of the fixed-point variant is in Floating point or fixed point.

Boost and buck-boost. At 100 kHz, the period has 4000 cycles, twice the buck's deadline. The boost measures up to 60 V, and the coefficients in counts per code change scale: NPWM q=4000×60/4095=58.6N_{\mathrm{PWM}}\,q = 4000 \times 60/4095 = 58.6NPWM​q=4000×60/4095=58.6, which calls for another format in Q15 fixed point.

Exercise 1

The float variant's interrupt computes u=0.3753u = 0.3753u=0.3753. What value goes to the CCR, and what duty cycle is applied? In which period does it take effect?

Answer

0.3753×2000+0.5=751.10.3753 \times 2000 + 0.5 = 751.10.3753×2000+0.5=751.1, truncated to 751: the applied duty cycle is 751/2000=0.3755751/2000 = 0.3755751/2000=0.3755, 0.00020.00020.0002 away from the computed value, below the step of 1/20001/20001/2000. With preload, it takes effect in the period after the sample.

Exercise 2

vref reaches the interrupt as NaN. What value goes to the CCR, and what happens to u1 and e1 afterwards?

Answer

The comparison e >= -E_MAX && e <= E_MAX is false for NaN, so ctrl_fault becomes 1 and ctrl_safe() switches both outputs off through HRTIM_ODISR: no new value goes to the CCR. The states return to DMIN and 0, and no NaN enters u1 or e1. The outputs stay off until the main loop clears the fault and re-enables them.
