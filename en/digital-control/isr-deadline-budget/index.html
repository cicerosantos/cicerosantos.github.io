Digital control

Interrupt deadline and budget

The control routine must write the CCR before the update event that copies it; the budget is the period minus the trigger, conversion, entry and computation, and only a measurement with a pin or the DWT, on production code, says whether it fits.

First, see: PWM timer and shadow registers, Computation and PWM delay

The control routine runs in an interrupt, and its write to the CCR must arrive before the update event that copies it into the active register (PWM timer and shadow registers). If it arrives in time, the delay is the one in Computation and PWM delay. If not, the value only takes effect a period later.

The deadline

At 200 kHz, the period is 5 µs. The HRTIM counts on the core clock (HRTIMSEL = 1, as in DPWM resolution and limit cycles), at 400 MHz, so the period has 2000 cycles. The sample is taken at the start of the period (as in the buck's frames), and the write to the CCR must fit before it ends:

Ts≥ttrigger+tconversion+tentry+tcomputation+twriteT_s \ge t_{\text{trigger}} + t_{\text{conversion}} + t_{\text{entry}} + t_{\text{computation}} + t_{\text{write}}Ts​≥ttrigger​+tconversion​+tentry​+tcomputation​+twrite​

Each term is counted from the start of the period. If the sum exceeds TsT_sTs​, the update event comes first, and the delay becomes (2+D) Ts(2+D)\,T_s(2+D)Ts​.

In the reference configuration, the CPU runs at 400 MHz and the AXI bus at 200 MHz (HPRE = 1000b, divide by 2), the VOS1 ceilings for silicon revision V (DS12110 revision 11, table 112). The HRTIM runs at 400 MHz, with D1CPRE = 0xxx (no division) and HRTIMSEL = 1; with HRTIMSEL = 0, it runs at 200 MHz.

What consumes the deadline

  • Trigger and conversion. The trigger reaches the ADC 1.5 to 2.5 ADC cycles after the timer, and a 12-bit conversion, with the 8.5-cycle window, takes 15 cycles: 300 ns with the ADC at 50 MHz (ADC trigger and sample instant).
  • Interrupt entry. On the Cortex-M4 it takes at most 12 cycles with zero-wait-state memory (Cortex-M4 TRM, section 3.9.1); the Cortex-M7 manual gives no figure, and it must be measured. It does not include two things, and the real entry is longer when they occur:
    • FPU lazy stacking. Entry stores the eight words of the basic frame (xPSR, PC, LR, R12 and R0 to R3). With the FPU in use, S0 to S15 and FPSCR are not stored yet: the core reserves the space, under the ASPEN and LSPEN bits of the FPCCR register (PM0253, section 4.7.2), and stores those registers only at the routine's first floating-point instruction. The cost falls inside the routine, and only a worst-case measurement shows it.
    • Flash wait states. Code and constants read from flash cost wait states on every read. In the reference, the flash needs 2 wait states at VOS1 with the AXI at 200 MHz and WRHIGHFREQ = 10 (RM0433, table 17): three AXI clock cycles per read, or six CPU cycles at 400 MHz.
  • Computation. The 2p2z equation has four multiplications and five additions or subtractions, plus saturation and the write. What that costs in cycles depends on the core and the FPU, and only measurement gives the number.

Fast code

On the STM32H7, the routine can run from ITCM (0x0000 0000, 64 KB, RM0433 section 2.4), with zero wait states (section 2.1.2), and the state can sit in DTCM (0x2000 0000, 128 KB, section 2.4). static alone puts nothing there: the routine and the state need their own sections, with __attribute__((section(...))) and matching sections in the linker script, and the routine must be copied to ITCM at start-up. Do not call library functions inside it. Outside the TCMs, the default memory map already puts SRAM in the data cache, with a write-back policy (PM0253, table 17): with the cache on, it goes through it with no setup at all, and the MPU changes those attributes.

Measuring

Measure with the production code, with the flash and cache as they will be on the board. There are two tools.

  • GPIO pin. The pair of BSRR writes in the The 2p2z in C, in the interrupt code makes a pulse whose width is the interrupt's duration. On the oscilloscope, alongside the PWM, you see the latency from the start of the period and the variation from one period to the next, the jitter.
  • DWT cycle counter. On Cortex-M3, M4 and M7, the DWT counts clock cycles in CYCCNT (Cortex-M7 TRM, table 11-1). The M0 and M0+ have no such counter; there, use the pin. On the Cortex-M7, and so on every STM32F7 and H7, the DWT has a software lock, DWT_LAR, that the M4 lacks: write DWT->LAR = 0xC5ACCE55 before enabling the counter. The LAR field exists only in CMSIS core_cm7.h, and on an M4 that line does not compile.
static uint32_t worst;                              /* worst measured case, in cycles */

void measure_init(void)                             /* once, at initialization */
{
    CoreDebug->DEMCR |= CoreDebug_DEMCR_TRCENA_Msk;
    DWT->LAR = 0xC5ACCE55;                          /* unlock the DWT: Cortex-M7 only */
    DWT->CYCCNT = 0;
    DWT->CTRL |= DWT_CTRL_CYCCNTENA_Msk;
}

void ADC_IRQHandler(void)
{
    uint32_t t0 = DWT->CYCCNT;                      /* at the start of the interrupt */
    /* ... control routine ... */
    uint32_t dt = DWT->CYCCNT - t0;                 /* at the end; unsigned subtraction survives the wrap */
    if (dt > worst) worst = dt;                     /* keep the worst case, not the average */
}

The DWT measures only from the routine's entry to its end. The trigger, the conversion and the interrupt entry are outside it, and the deadline includes all three. To measure from the start of the period, read the HRTIM counter at the end of the routine: it already counts from the start of the period.

Interrupt overrun

There is an overrun when the routine ends after the update event. The write misses the event, the value takes effect a period later, and the delay goes from (1+D) Ts(1+D)\,T_s(1+D)Ts​ to (2+D) Ts(2+D)\,T_s(2+D)Ts​. The usual overrun shows only on the pin, when the routine's pulse runs past the update event's instant, or on the counter. The ADC's OVR flag only catches a delay of about a whole period, or a blocked interrupt, and only in the right mode. With the default, OVRMOD = 0, DR is an eight-entry FIFO. After one missed read, the routine reads the previous sample and stays one sample late, with no end; OVR only rises after eight accumulated missed reads, when the FIFO is full (RM0433, section 25.4.27, p. 962). With OVRMOD = 1 (bit 12 of ADC_CFGR), OVR rises at the first missed read, and DR holds the latest conversion (RM0433, section 25.4.27). The routine in The 2p2z in C, in the interrupt uses that mode and handles the case.

Exercise

Suppose, for the exercise only, that the trigger and the conversion take 0.5 µs together, and that the interrupt entry plus the computation take 1.8 µs, in a 5 µs period. Is there room left for the write to the CCR? How much?

Answer

5−0.5−1.8=2.75 - 0.5 - 1.8 = 2.75−0.5−1.8=2.7 µs of margin. Yes, the write fits, with room to spare.
