Input feedforward

The firmware measures the input and recomputes the duty before the output moves: in the buck, d = u·V_in0/v_in normalizes the loop gain and nearly cancels G_vg; in the buck-boost, the law V/(v_in + V) corrects only the slow part.

In the firmware

#define DMIN      0.0f
#define DMAX      0.9f                  /* buck; 0.8f in the buck-boost */
#define VIN_FLOOR 1.0f                  /* an invalid reading below this */

/* Buck: u is the duty the 2p2z asks for, designed at vin0.
   With d = u·vin0/vin, the product d·vin stays at u·vin0. */
float ff_buck(float u, float vin, float vin0)     { return u * (vin0 / vin); }
float ff_buck_inv(float d, float vin, float vin0) { return d * (vin / vin0); }

/* Buck-boost: d = Vo/(vin + Vo), with Vo = vin0·u/(1 − u), the output u
   would give at vin0; top and bottom multiplied by (1 − u). */
float ff_buckboost(float u, float vin, float vin0)
{
    float vc = vin0 * u;
    return vc / (vc + vin * (1.0f - u));
}
float ff_buckboost_inv(float d, float vin, float vin0)
{
    float vd = vin * d;
    return vd / (vd + vin0 * (1.0f - d));
}

float duty_clamp(float d)
{
    if (!(d >= DMIN)) d = DMIN;
    if (d > DMAX) d = DMAX;
    return d;
}

typedef struct { float a2, b0, b1, b2, u1, u2, e1, e2, vin0; } ctrl_t;

/* One step of the buck's interrupt: vout and vin sampled on the same trigger,
   e = vref − vout. Returns the d that goes to the CCR. */
float isr_buck(ctrl_t *c, float e, float vin)
{
    if (!(vin >= VIN_FLOOR)) return DMIN;   /* NaN or no input: no pulse */
    float u = c->u1 + c->a2 * (c->u1 - c->u2)
            + c->b0 * e + c->b1 * c->e1 + c->b2 * c->e2;
    float d = duty_clamp(ff_buck(u, vin, c->vin0));
    u = ff_buck_inv(d, vin, c->vin0);       /* the u of the applied d: no windup */
    c->u2 = c->u1;  c->u1 = u;
    c->e2 = c->e1;  c->e1 = e;
    return d;
}

The 2p2z's states keep uuu, not ddd: the law stays outside the compensator, and the velocity form of The 2p2z in C, in the interrupt does not change. The limit applies to ddd, and uuu is recomputed from the limited ddd. With the input below Vin0V_{in0}Vin0​, ddd reaches DMAX while uuu is still DMAX⋅vin/Vin0\cdot v_{in}/V_{in0}⋅vin​/Vin0​; a uuu limited only at DMAX would keep growing, and the loop would be slow to leave the limit (Anti-windup and duty saturation). In the buck-boost, the step is the same, with ff_buckboost and ff_buckboost_inv. Both samples come from the same ADC trigger, so the input and the output are from the same instant. An invalid input reading turns the pulse off instead of dividing by zero.
