Ponto fixo Q15

Sem FPU, os coeficientes e os sinais viram inteiros escalonados: formatos Qm.n, multiplicação Q15 com arredondamento e saturação, e a escala dos coeficientes do 2p2z do buck.

Antes, veja: Compensador 2p2z

O compensador 2p2z tem coeficientes como 0,23114 e −0,43413. Com unidade de ponto flutuante, eles entram no código como estão. Sem ela, cada número vira um inteiro com uma escala implícita.

Float ou ponto fixo?

  • Com FPU (Cortex-M4F, M7, M33 com FPU, como STM32G4, F4 e H7): use float. A FPU de precisão simples faz multiplicação e soma em um a três ciclos (valores típicos dos manuais, não medidos aqui), e a mantissa de 24 bits sobra para este laço.
  • Sem FPU (Cortex-M0 e M0+, como STM32G0 e C0): cada operação em float vira uma chamada de biblioteca de, tipicamente, dezenas de ciclos. Com um período de 5 µs e um núcleo de 64 MHz, há só 320 ciclos por período. Aqui se usa ponto fixo.

A dupla precisão escondida

Numa FPU de precisão simples, 0.5 é um double, e x * 0.5 é calculado em software. Escreva 0.5f, e compile com -Wdouble-promotion para o compilador apontar os casos.

Q2.13 cobre de −4 a 4 em passos de 1,22×10−41{,}22\times10^{-4}1,22×10−4: troca resolução por folga. O produto de dois números Q15 tem 30 bits de fração e cabe em 32 bits. Para voltar a Q15, soma-se meio passo (2142^{14}214) e desloca-se 15 bits:

#include <stdint.h>

static inline int16_t sat16(int32_t x)          /* satura em vez de dar a volta */
{
    return x > INT16_MAX ? INT16_MAX : x < INT16_MIN ? INT16_MIN : (int16_t)x;
}

static inline int16_t q15_mul(int16_t a, int16_t b)
{
    int32_t p = (int32_t)a * b;      /* Q30: o cast vem antes da multiplicação */
    p += 1 << 14;                    /* arredonda em vez de truncar */
    return sat16(p >> 15);           /* -1 * -1 = +1 não cabe em Q15: satura */
}

Três armadilhas

  • Estouro: sem saturação, 0,9+0,20{,}9 + 0{,}20,9+0,2 em Q15 vira −0,9-0{,}9−0,9. Uma razão cíclica que salta de 0,9 para −0,9 é o pior erro possível. Nos Cortex-M3 e M4, o CMSIS oferece __SSAT(x, 16), que satura em uma instrução.
  • Truncamento: p >> 15 sem o meio passo arredonda sempre para baixo, um viés que o integrador acumula.
  • Deslocamento de negativos: em C99, >> de um número negativo depende da implementação. No GCC para ARM ele é aritmético; confira no seu compilador.

Para somar vários produtos, use um acumulador de 64 bits. Cada produto Q15 × Q15 já ocupa 31 bits, e dois deles somados podem estourar 32 bits. No Cortex-M4, a instrução SMLAL multiplica e acumula em 64 bits em um ciclo, segundo o manual do núcleo. No M0 não há essa instrução, e o compilador emula a conta em várias.

As unidades também contam. O firmware recebe códigos do ADC e escreve contagens no CCR. Multiplicando os coeficientes por NPWM q=850×4,884 mV=4,15N_{\mathrm{PWM}}\,q = 850 \times 4{,}884\ \text{mV} = 4{,}15NPWM​q=850×4,884 mV=4,15, eles passam a valer em contagens por código: 0,9600{,}9600,960, −1,802-1{,}802−1,802 e 0,8460{,}8460,846. Agora b1b_1b1​ passa de 1, e o formato precisa de folga: Q1.14 basta, e Q2.13 aceita projetos maiores. O script abaixo quantiza os coeficientes e mede o efeito:

import numpy as np
fs, q, N = 200e3, 20/4095, 850
b = np.array([0.23114164, -0.43413087, 0.20384645]); p = 0.15183580
a1, a2 = -(1 + p), p                       # denominador 1 + a1 z^-1 + a2 z^-2
K = N * q                                  # de razão cíclica/volt para contagens/código
ki = b.sum() / (1 - a2)                    # passo do integrador por amostra
for n in (15, 14):                         # a1 e a2 na mesma escala: 1 + a1 + a2 = 0 exato
    A1, A2 = round(a1 * 2**n), round(a2 * 2**n)
    print(f"a em Q{15 - n}.{n}", A1, A2, 2**n + A1 + A2)   # Q0.15: -37743 não cabe em int16
for name, n, scale in [("Q15 d/V", 15, 1), ("Q2.13 d/V", 13, 1), ("Q4.11 d/V", 11, 1),
                       ("Q2.13 cont/cod", 13, K), ("Q1.14 cont/cod", 14, K)]:
    B = np.round(b * scale * 2**n)         # os inteiros gravados no firmware
    bq = B / 2**n / scale
    a2q = np.round(a2 * 2**15) / 2**15     # a2 em Q15: 4975; a1 = -(1 + a2) implícito
    f = np.abs(np.log(np.roots(bq))) * fs / (2 * np.pi)
    print(name, B.astype(int), np.round(f), f"{100 * (bq.sum() / (1 - a2q) / ki - 1):+.1f} %")

Nos conversores

Buck. Os coeficientes em contagens por código, em Q2.13, ficam a 0,5 % do ganho integral exato e mantêm a margem de 41,3°. É a variante em ponto fixo de O 2p2z em C, na interrupção. O formato Q2.13 cobre até ±4, mas o projeto agressivo do buck chega a b1=−6,56b_1 = -6{,}56b1​=−6,56 contagens por código, e o instável a −8,99. Trocar de projeto pode pedir outro formato, e o código deve verificar a faixa dos coeficientes antes de gravá-los.
